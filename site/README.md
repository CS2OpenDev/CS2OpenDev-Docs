# CS2 Reference site

Astro + Starlight front end for the generated CS2 reference. Every page is rendered
from the JSON the Python generator writes into `../docs/generated/`. The site never
reads the Markdown under `../docs/generated/` and never writes into it.

## Commands

```bash
npm install
npm run dev        # copies artifacts, then astro dev on http://localhost:4321/CS2OpenDev-Docs/
npm run build      # copies artifacts, then a full static build into dist/
npm run preview    # serves dist/ at the same base path
```

`predev` and `prebuild` run `scripts/copy-artifacts.mjs`, which mirrors
`../docs/generated/downstream-codegen-schemas/` into `public/generated/` so the JSON
artifacts keep serving at their current URLs. Those copies are gitignored.

### Iterating without building 4,400 pages

```bash
SITE_SUBSET=50 npm run build                      # first 50 entities per module
SITE_SUBSET=5 SITE_INCLUDE=server/CCSPlayerPawn,server/CBaseEntity npm run build
```

`SITE_SUBSET=<n>` limits the entity routes to the first n entities per module.
`SITE_INCLUDE=<module>/<Name>,...` pins specific pages into a subset build so a page
you are working on is always emitted. Both are ignored by a plain `npm run build`.

`CS2_DOCS_ROOT` overrides the repository root the data is read from; by default the
loader walks up from the working directory looking for
`docs/generated/downstream-codegen-schemas`.

## What reads what

```
../docs/generated/downstream-codegen-schemas/cs2_schema.json
        │  read once with fs, cached per process
        ▼
src/lib/data/schema.ts        entities, name/module/key indexes, children, reverse
        │                     type index, layout flattening, bitfield bit indexes,
        │                     enum value wrapping, cross-project integrity check
        ├── src/lib/tree.ts           inheritance trees as nested <details>
        ├── src/lib/diagram.ts        mermaid classDiagram edges
        ├── src/lib/urls.ts           every href on the site, base path included
        ├── src/lib/modules.ts        per-module glosses
        └── src/lib/paths.ts          repository root and artifact directory lookup
        │
        ▼
src/components/EntityArticle.astro    the entity page body
src/components/Mermaid.astro          lazy client-side mermaid with pan and zoom
        │
        ▼
src/pages/schemas/index.astro             /schemas/
src/pages/schemas/[module]/index.astro    /schemas/<module>/
src/pages/schemas/[module]/[entity].astro /schemas/<module>/<TypeName>/
```

`astro.config.mjs` loads the same index at config time to build the sidebar (one link
per module, one per protobuf file) and the redirect table from the old
`/generated/schemas/...` paths. Nothing uses `autogenerate`: an autogenerated sidebar
over the entity pages would put 4,400 links into every page of the site.

Other page families (protobufs, convars, commands, game events, items, and so on) read
`../docs/generated/data/*.json` and belong in `src/lib/data/` as siblings of
`schema.ts`, one module per family.

## URLs

| Page | Path |
|---|---|
| Type | `/schemas/<module>/<TypeName>/` with case preserved and `::` written as `.` |
| Module index | `/schemas/<module>/` |
| Schemas index | `/schemas/` |
| JSON artifacts | `/generated/downstream-codegen-schemas/...` |

The old Jekyll paths under `/generated/schemas/` redirect to the new ones. Astro cannot
enumerate the parameters of a dynamic redirect in a static build, so `astro.config.mjs`
writes one redirect entry per entity and module.

## Conventions

- Anything under `dist/`, `.astro/`, `node_modules/` and `public/generated/` is build
  output and is gitignored.
- Entity pages are static HTML with no island. Islands belong on the big filterable
  tables (convars, commands, items) where they earn their hydration cost.
- Offsets, sizes and hex values live in `<td class="offset">` / `<td class="value">`
  so the theme can give them tabular figures.
- The theme lives in `src/styles/custom.css` and is registered through Starlight's
  `customCss`. Mermaid styles live inside `src/components/Mermaid.astro`.
