Two entities that draw text with no layout file. A `point_worldtext` above the spawn shows the score and announces each round's winner in that team's colour. A `game_text` tells the player who got a kill whom they eliminated.

## Map setup

| Entity | Name | Properties |
|---|---|---|
| <ScriptRef entity="point_worldtext" /> | `gallery_score_text` | `justify_horizontal`: Center, `fullbright`: on, a large `font_size` |
| <ScriptRef entity="game_text" /> | `gallery_kill_text` | **All Players** flag off; `y` about `0.7`; `holdtime` `2` |
| <ScriptRef entity="point_script" /> | any | `cs_script`: `maps/scripts/gallery_text.vjs` |

## How it works

- Neither entity has a script class, so the script reaches them through inputs: <ScriptRef entity="point_worldtext" input="SetMessage" />, <ScriptRef entity="point_worldtext" input="SetTextColor" />, <ScriptRef entity="game_text" input="SetText" /> and <ScriptRef entity="game_text" input="Display" />.
- With **All Players** off, `game_text` shows only to the input's activator, so the script passes the killer's pawn as `activator`.
- Input names are plain strings and nothing checks them when the script compiles. The [Entity I/O](../../../entities/) pages list every input each entity accepts, and the generated `cs2_entity_io.d.ts` typings catch a typo in the editor.

## Make it yours

- `game_text` has four channels, and a new message replaces whatever is showing on its channel. Put messages that can overlap on separate entities and channels.
- `point_worldtext` also takes `SetIntMessage`, which suits a bare number such as a countdown.
