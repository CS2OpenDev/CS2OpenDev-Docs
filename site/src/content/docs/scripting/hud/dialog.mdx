A dialog that appears when a player finishes loading, greets them by name, and stays until they click **Got it**. It follows the pattern of Valve's `cs_script_demo` welcome dialog, plus a per-player dialog variable.

<HudSample slug="dialog" />

## Map setup

| Entity | Name | Properties |
|---|---|---|
| <ScriptRef entity="custom_hud_layout" /> | `gallery_dialog_layout` | `layout`: `panorama/layout/custom_game/gallery_dialog.vxml` |
| <ScriptRef entity="point_script" /> | any | `cs_script`: `maps/scripts/gallery_dialog.vjs` |

## How it works

- The layout starts with a `Dismissed` class on `#dialog`, which sets `opacity: 0`. Showing the dialog removes that class for one player; closing it adds it back.
- `text="Welcome, {s:name}"` reads the `name` dialog variable. The script sets it on the Label's own id with <ScriptRef name="CustomHudLayout.SetDialogVariableStringForPlayer" />, so each player sees their own name.
- <ScriptRef name="CustomHudLayout.SetInputCaptureEnabled" /> gives the player a cursor and takes away movement until it is released. Release it wherever you hide the dialog, or the player stays frozen.
- Clicks arrive through <ScriptRef name="OnCustomHudClicked" />. Compare `layout` as well as `buttonId`: every layout's clicks reach the same handler.
- On disconnect, <ScriptRef name="CustomHudLayout.ResetForPlayer" /> clears the slot, because the next player to connect can get the same slot number.

## Make it yours

- To show the dialog only once per player across map changes, record the dismissal with `Instance.SetSaveData`. It writes to disk synchronously on every call, so write once, not every tick.
- To add buttons, give each `<Button>` an `id` and branch on `buttonId`. A `<Button>` accepts only `id` and `class`.
